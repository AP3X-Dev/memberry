[project:ag3ntic] WQ-15 fixed 2026-06-10. BUG: DELETE/archive of an employee in a multi-employee workspace returned HTTP 500 and rolled back (after the container was already removed, leaving a ghost the S7 reconciler then resurrected). ROOT CAUSE: delete_runtime (orchestrator.py) and the reconciler's _finish_delete both called docker_client.remove_network(runtime_network_name(workspace_id)) UNCONDITIONALLY, but the per-workspace runtime network is SHARED by every employee in the workspace (ensure_network is idempotent and reused at each launch). Docker refuses to remove a network with active endpoints ("has active endpoints", APIError 403), so the teardown raised and rolled back. FIX (full class): added orchestrator._reap_workspace_network_if_unused(session, runtime) — counts other non-deleted runtime_instances in the workspace (id != self, deleted_at null, status != deleted); removes the network only when zero remain. Both teardown paths use it. Plus defense-in-depth: docker_client.remove_network now treats active-endpoints (status 403 / "active endpoints" in message) as a non-fatal skip (provision-vs-delete race). Regression test test_delete_keeps_shared_network_when_a_sibling_runtime_remains (FakeDocker asserts removed_networks==[] with a sibling present; the existing single-employee test still asserts the network IS reaped as the last one).
