[project:ag3ntic] Hardening discovery D2 fixed (commit 2d9688c). The operational cadence/limit knobs in platform_core/config.py Settings (worker_sweep_interval_seconds, agent_runner_poll_seconds, api_rate_limit_per_minute, chat_model_timeout_seconds, chat_model_max_tokens, agent_task_default/max_steps, agent_task_artifact_retention_days, agent_task_artifact_signed_url_ttl_seconds, runtime_container_pids_limit, codex_cli_timeout_seconds) were bare ints/floats with no bounds. A misconfig silently broke an operational invariant rather than failing loud: a <=0 cadence busy-loops the reconciler/poller via asyncio.sleep(0); a <=0 rate limit deny-alls; <=0 timeouts/budgets make a model call that can never emit a token; a 0 max_steps makes a task that can never act; a default_max_steps above the hard max is self-contradictory. Convention applied (mirrors item #15 standing_grant_ttl_seconds): bound every such knob fail-closed at config-construction time with pydantic Field(ge=,le=) so an out-of-range env value raises ValidationError at boot. Reused bounds already present elsewhere: employees/spec.py RuntimeResources pids_limit (ge=64,le=4096) and max_tokens (ge=1,le=200_000), tool_capsules/manifest.py timeout_seconds (ge=1,le=3600), workspaces/schemas.py agent_task_artifact_retention_days (ge=1,le=365). Added a model_validator(mode='after') enforcing the cross-field invariant agent_task_default_max_steps <= agent_task_max_steps (matches the documented 80<=250). TDD via tests/test_config_operational_bounds.py (15 tests). Suite 251 -> 266 passed; cleanliness gate PASS. Convention takeaway: config values that gate an operational/security boundary must be bounds-validated at the edge (config construction), never trusted as bare ints.
