[project:ag3ntic] Hardening item #6 fixed (commit 20d5d4b, branch morph/opt-hardening). Root cause: HermesRuntimeAdapter.stream_run_events drained the per-run asyncio.Queue until the terminal _DONE sentinel but never removed the finished _Session from self._sessions. The adapter is designed to be reusable (sessions keyed by ACP session_id for the resume/session_load path), so a reused adapter stranded one ACP client + docker-exec transport + daemon reader thread per run; only the adapter-wide close() reclaimed them (it loops _sessions). Fix: wrap the drain in try/finally and call a new best-effort _evict_session on terminal/cancellation — cancel any live pump_task, await client.close() (joins the reader thread, set in item #4), drop the _sessions entry. Consequences: close() is now an idempotent no-op for finished runs, _session_for_run correctly raises hermes_no_session for a completed run (no stale match on run_id reuse), and the worker's finally: adapter.close() in execute_acp_run is harmless after the stream is fully drained. Convention reused from item #5: the cleanup close() is wrapped in try/except + log.exception so a wedged close never masks the run error re-raised right after the finally. TDD: tests/test_hermes_adapter.py::test_stream_evicts_session_after_terminal_event drains a full run with NO adapter.close() and asserts session gone + client._closed + pump_task.done().
