USER-REPORTED DEFECT: agent replied with a hallucinated `![Google screenshot](sandbox:/tmp/google_screenshot.png)` markdown path instead of an inline artifact. Diagnosis from live DB: browser.screenshot tool calls FAILED (2x), zero artifact.produced events. Compounded causes: (1) the mcp-demo-browser sidecar was running a pre-screenshot image, then I docker-rm'd it during the B5 deploy and NOTHING re-ensured it mid-session — its container_resources tracking row had been reaped so the worker resweep had nothing to restore (re-ensure only fires on launch/resume/attach); (2) on tool failure the model bluffed a sandbox path; (3) computer.screenshot returns raw image/* bytes that decode_backing_response text-mangles (never persisted); (4) artifacts were live-turn-only (reset on chat.run_started; gone after history materialization/reload).

CLASS FIXES (commit bbc4034, deployed api+web, suite 1113 green): shim.dispatch_backing_with_reensure — httpx.ConnectError/ConnectTimeout to a CONTAINER_BACKED_TYPES capability triggers ensure_capability_sidecar once + one retry (sidecar loss now self-heals at the next tool call, independent of tracking rows); shim.artifact_payload_from_response — artifact actions (screenshot/download_file) with binary content-type (image/*, octet-stream, pdf) wrap resp.content as content_b64 BEFORE decode (covers computer.screenshot); the model-facing tool result for persisted artifacts now carries displayed_to_user:true + an explicit note "already displayed inline, do NOT invent file paths" (anti-hallucination); chat materialize_assistant_messages collects artifact.produced events into Message.attachments + serialize_message exposes them + EmployeeChat renders ArtifactCard inside history AgentMsg (durable across reloads; live-turn copies clear after refreshHistory to avoid double-render).

LESSONS: (a) when re-pinning a sidecar image, docker-rm'ing the old container leaves a dead window — the lazy re-ensure now closes that class; (b) tool-result text is the ONLY channel to stop model path-hallucination — always state what the platform did with a file; (c) live-turn-only UI state is not "done" for chat features — durability through materialization is part of the definition of done.
