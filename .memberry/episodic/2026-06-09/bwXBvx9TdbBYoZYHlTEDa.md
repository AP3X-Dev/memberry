[project:skill-jar] Added category-based selective install (commit 8c61d7e). VERIFIED PLUGIN FACTS that drove the design: /plugin install is per-plugin and atomic (no installing a subset of one plugin's skills) -> categories require MULTIPLE plugins in one marketplace. A plugin's skills must live INSIDE its own dir (install copies the plugin dir to cache; ../ forbidden; files outside not copied). The docs' blessed cross-plugin sharing mechanism is SYMLINKS (dereferenced into cache) but those are Windows/git-hostile, so we avoided them. marketplace.json supports category/tags/keywords fields but the /plugin browse UI is NOT documented to filter by them. CHOSEN ARCHITECTURE: skills moved under category dirs (development/<skill>/SKILL.md); the folder a skill sits in IS its category (single source of truth, no frontmatter field to drift). Each category = its own plugin: skill-jar-development (source ./development, skills ./<skill>) + a skill-jar bundle (source ./, skills ./<category>/<skill>). No symlinks needed because each skill is in exactly one category. Tooling: scripts/jarlib.py = shared discovery (discover_skills walks <cat>/<skill>/SKILL.md; role-skill templates excluded; SKIP_DIR_NAMES for infra dirs); scripts/gen-plugins.py generates marketplace + bundle + per-category plugin.json with --check mode; gen-index.py now category-aware (skills.json gained a category field); audit-jar.py walks category depth and delegates plugin drift to gen-plugins.py --check (negative-tested: stale manifest -> exit 1). Adding a category = drop a skill in marketing/ (placeholder dir exists with README) + regenerate; its plugin appears automatically, empty categories ship nothing. Intra-development sibling cross-refs survived the move unchanged (only README top-level links needed updating). Install: /plugin install skill-jar-development@skill-jar (one category) or skill-jar@skill-jar (everything). Gate now 63 checks (was 65 — fewer because plugin checks consolidated into one gen-plugins delegation).
